# 피그마 화면 → PPT 자동 삽입 사용 안내

피그마에서 내보낸 화면 이미지를 PPT의 정해진 자리에 자동으로 넣어 줍니다.
화면을 고칠 때마다 PPT에서 이미지를 하나씩 바꿔 넣을 필요가 없습니다.

준비할 것은 네 가지입니다.

0. 작업할 **프로젝트 폴더** 만들기 (처음 한 번)
1. 피그마 프레임 이름을 **화면 ID**로 맞추기
2. PPT에서 이미지가 들어갈 자리에 **마커 도형** 넣기
   (화면 정의서처럼 슬라이드 표에 `화면ID`가 있고 화면 이미지가 이미 들어가 있으면 생략 가능)
3. 피그마에서 export하기 — **다운로드 폴더**에 받아 두면 실행할 때 자동으로 가져갑니다

그다음 Claude에게 "IMS 프로젝트에 피그마 화면 넣어줘"처럼 요청하면 됩니다.

## 0. 처음 한 번만: 설치

1. 이 저장소를 내려받습니다.
   - GitHub 페이지에서 **Code → Download ZIP** 후 압축을 풀거나,
   - `git clone https://github.com/shinaesoh/figma-ppt-insert.git`
2. Python(3.9 이상)이 없으면 [python.org](https://www.python.org/downloads/)에서 설치합니다.
   설치 화면에서 **Add python.exe to PATH**를 꼭 체크하세요.
3. 내려받은 폴더에서 필요한 패키지를 설치합니다.

   ```bash
   pip install -r requirements.txt
   ```

4. 이 폴더를 Claude Code(데스크톱 앱의 Code 탭 등)에서 엽니다. 스킬은 자동으로 인식됩니다.

## 프로젝트 폴더 만들기

원본 PPT, 이미지, 결과물은 **프로젝트별로** 따로 관리합니다. 화면 정의서·제안서처럼 문서가 다르면 프로젝트를 나누세요.

Claude에게 "**3D-Map-Editor 프로젝트 만들어줘**"라고 요청하면 아래 폴더가 생깁니다.

```
figma-ppt-insert/
└── projects/
    ├── IMS/
    │   ├── 01_template/      ← 원본 PPT 1개
    │   ├── 02_images/        ← 화면별 최신 피그마 이미지 (+ _archive)
    │   ├── 03_output/        ← 결과 PPT (+ _archive)
    │   └── insert_log.md     ← 실행 기록 (자동 생성)
    └── 3D-Map-Editor/
        └── ...
```

- 프로젝트가 없으면 Claude가 먼저 프로젝트 이름을 물어봅니다. **기획서 파일명에 들어간 이름**으로 지으면 나중에 찾기 좋습니다.
  (예: `AAIA_AD02_IMS_화면 정의서_v1.0_20260922.pptx` → `AAIA_AD02_IMS`)
- 프로젝트 이름에는 `\ / : * ? " < > |` 문자를 쓰지 마세요. 영문·숫자·하이픈을 권장합니다.
- 프로젝트 폴더 안의 파일은 GitHub에 올라가지 않습니다(각자 PC에만 보관).
- 아래 설명의 `01_template`, `02_images`, `03_output`은 모두 **해당 프로젝트 폴더 안**을 뜻합니다.

## 1. 피그마: 프레임 이름을 화면 ID로 바꾸기

export한 파일 이름은 프레임 이름과 같습니다. 그래서 프레임 이름이 곧 화면 ID입니다.

1. 왼쪽 **Layers** 패널에서 화면 프레임을 더블클릭합니다.
2. 이름을 화면 ID로 바꿉니다. 예: `SCR-MAIN-001`
   - 영문 대문자, 숫자, 하이픈(`-`)만 쓰는 것을 권장합니다.
   - 공백, 슬래시(`/`), 괄호는 쓰지 마세요. 슬래시는 피그마가 폴더로 바꿔 버립니다.
3. 같은 화면 ID는 한 번만 씁니다.

## 2. 피그마: export 설정 (PNG 2x)

1. 프레임을 선택합니다. 여러 개를 한 번에 선택해도 됩니다.
2. 오른쪽 패널 맨 아래의 **Export** 옆 **+** 를 누릅니다.
3. 배율은 **2x**, 형식은 **PNG**로 설정합니다.
4. **Export** 버튼을 누릅니다.

파일 이름이 `SCR-MAIN-001@2x.png`처럼 나와도 괜찮습니다. 끝에 붙는 `@2x`는 자동으로 무시합니다.

**해상도 확인**: 배율 대신 `512w`처럼 너비를 지정하거나 1x로 내보내면 이미지가 작아져 PPT에서 글자가 흐릿합니다.
예를 들어 1440px 너비 화면을 2x로 내보내면 2880px 정도가 정상입니다.
이미지가 PPT에 표시되는 크기에 비해 작으면(150ppi 미만) 실행 결과의 **확인 필요**에 경고가 나옵니다.
그 화면만 2x로 다시 export하고 다시 실행하세요.

## 3. 이미지 가져오기

이미지는 `02_images` 폴더 한 곳에 **화면 ID당 1개**(가장 최신본)만 모아 둡니다. 폴더만 열면 지금 쓰이는 화면 전체가 한눈에 보입니다.
새 export로 바뀐 이전 이미지는 `02_images/_archive/`에 자동으로 보관됩니다.

```
projects/IMS/
└── 02_images/
    ├── UI-IMS-2001.png          ← 화면별 최신 이미지
    ├── UI-IMS-2002.png
    ├── UI-IMS-2006.png
    └── _archive/
        ├── UI-IMS-2001_20261002_1430.png   ← 교체된 이전 이미지 ({화면ID}_{export 시각})
        └── Figma export.zip                ← 가져온 zip 원본
```

### 기본: 다운로드 폴더에서 자동으로 가져오기

피그마에서 export한 파일을 **다운로드 폴더**(`C:\Users\{사용자}\Downloads`)에 그대로 두고 실행을 요청하면 됩니다.

- **오늘 받은 파일**만 가져옵니다. 파일 이름이 PPT의 화면 ID 형식(예: `UI-IMS-2001`, 새 화면 `UI-IMS-2402`)인
  `.png`·`.jpg`, 그리고 여러 프레임을 한 번에 export했을 때 생기는 `.zip`이 대상입니다. 관계없는 파일은 건드리지 않습니다.
- 가져온 파일은 다운로드에서 `02_images/{화면ID}.png`로 **이동**합니다. 이름의 `@2x`, ` (1)`은 떼고 저장합니다.
  같은 화면의 기존 이미지는 `_archive`로 옮겨집니다. zip은 화면 이미지만 풀어 넣고 zip 파일은 `_archive`에 보관합니다.
- 같은 화면 ID 파일이 여러 개면 **가장 최근 파일**을 가져오고, 나머지는 다운로드에 남겨 둔 채 **확인 필요**에 알려 줍니다.
  프로젝트에 이미 더 최근 이미지가 있으면 가져오지 않습니다.
- **어제·그제** 받은 화면 ID 파일이 다운로드에 남아 있으면 가져오지 않고 목록만 알려 드립니다.
  넣고 싶으면 "그것도 넣어줘"라고 말씀해 주세요 (`--download-days 3`).
- 다운로드를 쓰지 않으려면 `--no-downloads`, 다른 폴더에서 가져오려면 `--downloads 경로`를 씁니다.

### 직접 넣기

`02_images` 폴더에 이미지를 바로 넣어도 됩니다. `UI-IMS-2001@2x.png`처럼 넣어도 실행할 때 `UI-IMS-2001.png`로 정리되고,
같은 화면의 이전 이미지는 `_archive`로 옮겨집니다. 같은 화면이 여러 개면 **수정 시각이 가장 최근인 파일**이 쓰입니다.

- `.png`, `.jpg`를 지원합니다. WebP·SVG·PDF 등 다른 형식이나 열리지 않는 파일은 건너뛰고 **확인 필요**에 표시합니다.
- 예전 방식의 날짜 폴더(`02_images/2026-10-02/`)가 있으면 첫 실행 때 같은 규칙으로 정리되고 날짜 폴더는 없어집니다.

## 4. PPT에 마커 도형 넣기

1. 원본 PPT에서 화면이 들어갈 자리에 **사각형**이나 **텍스트 상자**를 그립니다.
   이 도형의 **위치와 크기**가 이미지가 들어갈 영역이 됩니다.
2. 도형 안에 아래 문구를 **그대로** 입력합니다. 다른 글자는 함께 넣지 마세요.

   ```
   [화면 교체 위치: SCR-MAIN-001]
   ```

3. 완성한 PPT 파일 **1개**를 `01_template` 폴더에 넣습니다.

주의할 점은 다음과 같습니다.

- 마커 도형을 **그룹으로 묶지 마세요.** 그룹 안 마커는 아직 지원하지 않습니다.
- 도형을 회전시키지 마세요. 회전은 무시하고 영역만 사용합니다.
- 같은 화면 ID를 여러 슬라이드에 써도 됩니다. 모든 자리에 같은 이미지가 들어갑니다.
- 영역 비율을 화면 비율과 비슷하게 그리면 여백이 거의 없습니다.

### 화면 정의서처럼 마커가 없는 경우

슬라이드 상단 표에 아래처럼 `화면ID` 칸이 있으면, 마커가 없어도 자동으로 교체됩니다.

| 화면ID | UI-IMS-2001 | 화면명 | ... |
|---|---|---|---|

- `화면ID` 칸 바로 오른쪽 값이 화면 ID입니다. 피그마 프레임 이름과 같아야 합니다.
- 그 슬라이드에서 **가장 큰 그림**을 기존 화면으로 보고, 같은 위치·크기·레이어에서 새 이미지로 바꿉니다.
  화면 위에 올려 둔 번호 배지나 점선 박스는 그대로 위에 남습니다.
- 새 이미지가 없는 화면은 기존 이미지를 그대로 둡니다. 바뀐 화면만 export해도 됩니다.
- 같은 화면 ID가 여러 슬라이드에 있으면 모두 같은 이미지로 바뀝니다.
  서로 다른 화면인데 ID가 겹쳐 있다면 PPT의 화면 ID를 먼저 고쳐 주세요.
- 한 슬라이드에 마커가 있으면 그 슬라이드는 마커 기준으로 처리합니다.

### 새 화면 슬라이드 추가 (화면 정의서)

PPT에 아직 없는 화면 ID의 이미지를 넣고 "**새 화면 슬라이드도 추가해줘**"라고 요청하면 슬라이드를 새로 만듭니다.

- 위치: 화면 ID 순서에 맞는 자리. 예) `UI-IMS-2006` → `UI-IMS-2005` 슬라이드 바로 다음
- 양식: 그 위치에서 가장 가까운 **유형이 '변경'인** 화면 슬라이드의 공통 틀(상단 표, 화면 영역 테두리, 로고, 페이지 번호)을 복제합니다.
  '유지' 슬라이드는 회색 배경이라 쓰지 않습니다. 원본 슬라이드의 화면 이미지, 번호 배지, 설명은 가져오지 않습니다.
- 화면ID 칸에는 파일명이 들어가고, 화면명·화면타입·유형·화면 경로는 `(확인 필요)`로 채워집니다.
- 화면 설명 자리에는 `[확인 필요]` 안내 텍스트 박스(Pretendard)가 생깁니다. 내용을 직접 채워 주세요.
- 뒤쪽 슬라이드의 페이지 번호(상단 표의 '페이지' 칸, 하단 번호)는 하나씩 밀려서 자동으로 고쳐집니다.
- 목차·개정 이력 같은 다른 페이지의 화면 목록은 바뀌지 않습니다. 로그의 **확인 필요**에 안내가 나옵니다.
- 요청하지 않으면 새 슬라이드를 만들지 않고, 그 이미지는 "이미지는 있는데 마커·화면ID 없음"으로만 표시됩니다.

## 5. 실행 요청하기

Claude Code에서 이렇게 요청하면 됩니다.

- "IMS 프로젝트에 피그마 화면 넣어줘" ← 오늘 다운로드한 export를 가져와서 넣음
- "IMS 피그마 export 반영해줘"
- "IMS 화면 교체 위치에 이미지 넣어줘, 영역 꽉 채우기로" ← 잘리더라도 영역을 꽉 채우고 싶을 때
- "IMS 피그마 화면 매칭 결과만 먼저 보여줘" ← 파일을 만들지 않고 확인만
- "IMS 피그마 화면 넣고 새 화면 슬라이드도 추가해줘" ← PPT에 없는 화면 ID는 슬라이드를 새로 만듦
- "프로젝트 목록 보여줘" / "3D-Map-Editor 프로젝트 만들어줘"

프로젝트가 하나뿐이면 프로젝트 이름을 생략해도 됩니다.

Claude는 바로 넣지 않고 먼저 **어떤 PPT 파일에 넣을지**(원본 파일명)와 다운로드에서 가져올 이미지 목록을 알려 준 뒤,
"이 파일에 넣을까요?"라고 확인을 받고 진행합니다.

직접 실행하려면 저장소 폴더에서 다음 명령을 입력합니다.

```bash
python .claude/skills/figma-ppt-insert/scripts/insert.py --project IMS
```

새 프로젝트 만들기는 `--new-project 이름`, 목록 보기는 `--list`입니다.

## 6. 결과 확인

모두 `projects/{프로젝트명}/` 안에 생깁니다.

| 위치 | 내용 |
|---|---|
| `03_output/{원본파일명}_최종.pptx` | 최신 결과물. 항상 1개 |
| `03_output/_archive/` | 이전 결과물. 실행할 때마다 자동으로 옮겨지며 최근 10개만 남습니다 |
| `insert_log.md` | 실행할 때마다 맨 아래에 결과가 추가됩니다 |

`insert_log.md`에서 꼭 볼 곳은 다음과 같습니다.

- **마커는 있는데 이미지 없음**: 이미지 파일명과 마커의 화면 ID가 다른 경우가 대부분입니다. 오타를 확인하세요.
  이 마커는 결과 PPT에 그대로 남아 있습니다.
- **이미지 없음 — 화면ID 슬라이드, 기존 화면 유지**: 새 이미지가 없어 기존 화면을 그대로 둔 슬라이드입니다.
  바뀐 화면만 export했다면 정상입니다.
- **이미지는 있는데 마커·화면ID 없음**: PPT 어디에도 그 화면 ID가 없습니다. 파일명 오타를 확인하거나, 불필요한 이미지면 무시하세요.
- **확인 필요**: 지원하지 않는 형식·손상된 파일, 해상도가 낮은 이미지, `02_images` 안의 다른 폴더, 그룹 안 마커, 다운로드에 같은 화면 파일이 여러 개인 경우 등

## 7. 화면을 다시 바꿀 때

- 새로 export한 이미지를 다운로드에 받아 두고 다시 실행합니다. 원본(`01_template`)은 그대로 두면 됩니다.
- 결과 PPT를 손봐서 그 파일을 새 원본으로 쓰고 싶다면, 그 파일을 `01_template`에 넣으세요
  (기존 원본은 빼야 합니다. 원본은 1개만 둡니다).
  이미 넣은 화면 이미지는 마커가 없어도 원래 영역에서 최신 이미지로 다시 교체됩니다.
  - 이때 넣은 이미지의 **이름(선택 창의 `FIGMA:화면ID`)이나 대체 텍스트를 바꾸면 교체 대상에서 빠집니다.**

| 경우 | 배치 |
|---|---|
| 비율이 비슷함 (차이 15% 이내, 예: 16:9 화면 ↔ 16:10 영역) | **상단 맞춤** — 영역 너비에 맞추고 위쪽 모서리 두 곳을 영역에 맞춤. 화면 위 번호 배지 위치가 유지됩니다. 화면이 더 짧으면 아래가 비고, 더 길면 아래쪽이 잘립니다 |
| 비율이 크게 다름 (팝업, 모바일 화면 등) | **가운데** — 화면 전체가 보이게 줄여서 영역 가운데에 놓습니다 |

영역을 꽉 채우고 넘치는 부분을 자르려면 "영역 꽉 채우기로"라고 요청하세요.
어떤 배치가 쓰였는지는 `insert_log.md`의 **배치** 열에서 볼 수 있습니다.

**결과 PPT에 Pretendard 폰트가 필요한가요?**
1차는 텍스트를 추가하지 않습니다. 원본 PPT의 폰트를 그대로 유지합니다.

## 2차 후보 (1차 범위 밖)

1차에서는 구현하지 않았고, 필요해지면 추가할 항목입니다.

- 텍스트 자동 채우기 (화면 설명·캡션 등. 추가 시 폰트는 Pretendard)
- 한 프로젝트에 여러 원본 PPT (`01_template`에 여러 개)
- 그룹 도형 안의 마커
- 회전된 마커 영역에 회전까지 반영
- 화면ID 표도 마커도 없는 슬라이드의 스크린샷 인식·교체
- 화면ID 슬라이드에서 교체 대상 그림 지정 (지금은 가장 큰 그림 자동 선택)
- 표 셀 안의 마커
- 마커별 배치 방식 지정 (예: `[화면 교체 위치: SCR-001 | fill]`)
- 정렬 기준 옵션 (위쪽 정렬 등. 긴 스크롤 화면용)
- 피그마 API로 export 자동화
- 화면 ID 오타 추정 제안 (비슷한 이름 안내)
